## django-stateless-mcp 0.1.7

No changes to the installed package — this release versions the repository's
documentation.

### Added

- **A long-running-jobs recipe.** `docs/recipes/long-running-jobs.md` documents
  the subscriptions-backed pattern the package's most user-visible workflow
  rests on: a tool starts a Celery task and returns instantly, the server
  pushes a `ResourceUpdated` event when the job finishes, and the client
  fetches the result through an ordinary permission-checked tool call. Covers
  the thin-signal rule, the parked-connection scale economics, the
  multi-process `SubscriptionBus` requirement, and the client-support caveat.
  (ADR-0029)

### Changed

- **The README and docs lead with benefits, not mechanism.** The README opens
  with a "Why use this" section (ordinary Django view, horizontal scaling,
  elicitation in concrete terms, long-running jobs, auth/permissions inside
  tools, structlog observability, `admin.py`-style registration), mirrored in
  condensed form on the docs home page; `why-stateless.md` gains the same
  concrete elicitation examples. Several claims were tightened in the process —
  spec-revision rather than SDK-version framing, and auth wording that does not
  overstate the Django bridge. (ADR-0029)
- The duplicate "Logging tool dispatch" section in `usage.md` was merged into
  "Structured request logging".
- **The example README is now a quick-start guide.** Six numbered steps —
  `docker compose up` → Inspector → connect → set Protocol Era to Modern → run
  a tool → run the elicitation round-trip — followed by linked detail
  sections. Docker is the primary boot path on every surface (the `just`
  targets remain as host-run alternatives), and the standalone Gotchas
  appendix is gone: each gotcha now lives inline at the step where it would
  bite, so a reader following the numbered steps cannot hit the
  Inspector legacy-era failure. (ADR-0030)
