## django-stateless-mcp 0.1.9

No changes to the installed package — this release versions the repository's
documentation.

### Changed

- **The docs now recommend OAuth as the production default.** `usage.md`'s
  bearer-auth section answers "what should production do?" directly: an open
  endpoint is fine in development but rarely right in production — pair
  [django-oauth-toolkit](https://django-oauth-toolkit.readthedocs.io/) (the
  authorization server, inside your project) with
  [django-oauth-toolkit-dcr](https://pypi.org/project/django-oauth-toolkit-dcr/)
  (Dynamic Client Registration, so MCP clients register themselves) and
  resolve the verified token to a real Django user. Authentication is framed
  as what switches on the package's access-control power: `request.user`
  stops being anonymous, tools gate with `user.has_perm(...)`, and
  `PermittedToolsFilter` shows each user only their tools. (ADR-0037)
- **The OAuth & permissions recipe opens with the why.** "The posture to
  default to in production", with a four-bullet benefits outline before the
  wiring: per-request authentication with clean `401`/`403` semantics, a real
  Django user from the verified token, per-tool access control (gating plus
  visibility), and clients that onboard themselves via DCR — no hand-issued
  client credentials. Worded as a strong default, not an absolute:
  private-network and session-fronted deployments remain legitimate, and
  nothing changes at runtime. (ADR-0037)
