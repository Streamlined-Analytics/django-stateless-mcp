## django-stateless-mcp 0.1.6

### Fixed

- **`mcp_view()` no longer 500s under `ATOMIC_REQUESTS`.** Django refuses to
  serve an async view on any database alias configured with
  `ATOMIC_REQUESTS = True` — cookiecutter-django's default — so every request
  raised `RuntimeError: You cannot use ATOMIC_REQUESTS with async views.`
  before reaching the view. `mcp_view()` now applies
  `transaction.non_atomic_requests` to the returned view for every configured
  alias; per-request transactions never applied to a view that could not run,
  so nothing is taken away, and tools needing transactional writes should hold
  their own `transaction.atomic()` blocks. A request-layer regression test now
  exercises the endpoint with `ATOMIC_REQUESTS` switched on. (#45, ADR-0031)
