## django-stateless-mcp 0.1.7

No changes to the installed package — this release versions the repository's
documentation.

### Added

- **A long-running-jobs recipe.** `docs/recipes/long-running-jobs.md` documents
  the subscriptions-backed pattern the package's most user-visible workflow
  rests on: a tool starts a Celery task and returns instantly, the server
  pushes a `ResourceUpdated` event when the job finishes, and the client
  fetches the result through an ordinary permission-checked tool call. Covers
  the thin-signal rule, the parked-connection scale economics, the
  multi-process `SubscriptionBus` requirement, and the client-support caveat.
  (ADR-0029)
- **Tool annotations, documented and demonstrated.** A new "Annotating tools
  (optional, encouraged)" section in `usage.md` explains each `2026-07-28`
  `ToolAnnotations` hint (`read_only_hint`, `destructive_hint`,
  `idempotent_hint`, `open_world_hint`, `title`) with the example's Book/Author
  tools as illustrations, links the version-pinned spec schema as the
  authoritative list, and restates that hints are untrusted — authorization
  stays inside the tool. The five Book/Author example tools now carry the
  annotations the docs describe, visible in `tools/list` and Inspector.
  (ADR-0034)

### Changed

- **The README and docs lead with benefits, not mechanism.** The README opens
  with a "Why use this" section (ordinary Django view, horizontal scaling,
  elicitation in concrete terms, long-running jobs, auth/permissions inside
  tools, structlog observability, `admin.py`-style registration), mirrored in
  condensed form on the docs home page; `why-stateless.md` gains the same
  concrete elicitation examples. Several claims were tightened in the process —
  spec-revision rather than SDK-version framing, and auth wording that does not
  overstate the Django bridge. (ADR-0029)
- The duplicate "Logging tool dispatch" section in `usage.md` was merged into
  "Structured request logging".
- **The example project is a Book/Author app, Django-docs style.** Real
  models (`Author`, `Book`) with a custom `example.can_update_authors`
  permission replace the imaginary widget demo: `delete_widget` →
  `update_author`, `count_users` → `count_books`, `add` → `list_books`,
  `multiply` → `book_slug`, plus a deliberately blocking `slow_book_report`
  (30 s) demonstrating that a slow tool occupies one worker thread, not the
  fleet. The Django admin joins the example as the primary way to toggle the
  permission (seeded `admin`/`admin` superuser), with the seed flags renamed
  to `--grant-update-authors`/`--revoke-update-authors` as the scriptable
  alternative. The `test_*` conformance fixtures are untouched. (ADR-0033)
- **The example README is now a quick-start guide.** Six numbered steps —
  `docker compose up` → Inspector → connect → set Protocol Era to Modern → run
  a tool → run the elicitation round-trip — followed by linked detail
  sections. Docker is the primary boot path on every surface (the `just`
  targets remain as host-run alternatives), and the standalone Gotchas
  appendix is gone: each gotcha now lives inline at the step where it would
  bite, so a reader following the numbered steps cannot hit the
  Inspector legacy-era failure. (ADR-0030)
- **The quick start's Inspector steps match Inspector v2.0.0's real UI.**
  Every step was re-driven against the current Inspector: the add-server flow
  (**Add Servers** → **+ Add manually**, Server ID / Transport / URL), the
  Protocol Era setting behind the card's **Settings** button, connecting via
  the card's toggle (one connection at a time), the self-populating Tools tab
  (there is no "List Tools" button), bearer auth via **Settings → Custom
  Headers**, and the reconnect-to-refresh recipe for a changed tool list.
  The slow-tool step drops the stale timeout advice — Inspector v2's default
  request timeout is unlimited. (ADR-0030)
- **The README and docs home open by defining MCP.** Two sentences on what an
  MCP server is — AI agents connecting in a controlled way, seeing and calling
  only the tools you expose under the permissions you enforce — before the
  package pitch, for readers arriving without MCP context.

### Build

- ruff 0.15.22 → 0.16.0 (dev dependency); its formatter's one change here is
  a joined f-string in a docs code block.
- The temporary `exclude-newer-package` exemption for `mcp` / `mcp-types` is
  gone: both are past the one-week supply-chain quarantine, and the global
  `exclude-newer = "1 week"` window now covers them naturally, closing the
  plan recorded in ADR-0005.
